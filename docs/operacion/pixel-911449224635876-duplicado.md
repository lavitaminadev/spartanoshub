# Pixel 911449224635876 asignado a dos empresas

El mismo Pixel figura con dos duenios distintos en `meta_pixels`. Viene de antes de que existiera
la regla de exclusividad, asi que ninguna pantalla lo creo de esta forma: lo dejo la migracion que
poblo la tabla en agosto con lo que habia entonces.

Mientras esten las dos filas, la comprobacion de exclusividad ya no falla —desde el arreglo mira
todas las filas y no una al azar— pero el Pixel **sigue perteneciendo a dos empresas a la vez**,
que es un estado que no deberia existir: las conversiones de dos negocios se mezclan en la misma
cuenta publicitaria.

Segun la operacion, el Pixel es **solo de GRDS**.

## 1. Mirar antes de tocar

```sql
SELECT p.id, p.pixel_id, p.name, p.client_id, c.name AS empresa, p.created_at
FROM meta_pixels p
LEFT JOIN clients c ON c.id = p.client_id
WHERE p.pixel_id = '911449224635876'
ORDER BY p.created_at;
```

Se esperan tres filas:

| name | client_id | que es |
|---|---|---|
| Pixel VitaminaHUB pruebas | `505723ab-…` | Prueba NO MODIFICAR — **sobra** |
| TOKENS GRDS | `NULL` | sin duenio, se hereda como Pixel de la agencia |
| TOKENS GRDS | `68d2f89a-…` | GRDS — **la buena** |

## 2. Respaldar las filas

```sql
CREATE TABLE meta_pixels_respaldo_20260927 AS
SELECT * FROM meta_pixels WHERE pixel_id = '911449224635876';
```

Comprobar que quedaron las tres:

```sql
SELECT COUNT(*) FROM meta_pixels_respaldo_20260927;
```

## 3. Quitar la asignacion que sobra

Solo la de la empresa de pruebas. **No se borra el Pixel**, se borra que figure como suyo:

```sql
DELETE FROM meta_pixels
WHERE pixel_id = '911449224635876'
  AND client_id = '505723ab-1b9e-415f-a6b9-e9b8526bc741';
```

Deberia afectar a **una** fila. Si dice otra cosa, parar y restaurar desde el respaldo.

## 4. Sobre la fila con `client_id` nulo

Esa marca el Pixel como «de la agencia», y es lo que heredan los locales de empresas que todavia
no tienen el suyo. **Si el Pixel es solo de GRDS, tambien sobra**, porque de lo contrario cualquier
empresa nueva empezaria midiendo en la cuenta de GRDS sin que nadie lo decidiera:

```sql
DELETE FROM meta_pixels
WHERE pixel_id = '911449224635876' AND client_id IS NULL;
```

Es una decision de operacion, no tecnica: hacerlo solo si se confirma que ninguna empresa debe
heredarlo.

## 5. Comprobar el resultado

```sql
SELECT p.pixel_id, p.client_id, c.name AS empresa
FROM meta_pixels p LEFT JOIN clients c ON c.id = p.client_id
WHERE p.pixel_id = '911449224635876';
```

Debe quedar solo la fila de GRDS. Despues, en la pantalla de Clientes, asignar el Pixel a GRDS
tiene que funcionar sin el aviso de «es de otra empresa».

## 6. Si algo sale mal

```sql
INSERT INTO meta_pixels SELECT * FROM meta_pixels_respaldo_20260927;
```

Y cuando todo este confirmado, retirar el respaldo:

```sql
DROP TABLE meta_pixels_respaldo_20260927;
```
